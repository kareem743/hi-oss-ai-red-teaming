# API management and Demo

Admin Settings is the source of truth. OpenAI and Anthropic keys are AES-256-GCM encrypted in D1 with a separate Cloudflare Worker secret BRITE_VAULT_KEY (32 random bytes, base64). Never return keys or ciphertext to browsers; keys can be replaced or removed. Preserve the master secret when deploying; do not rotate without re-encrypting existing keys. Only fixed provider URLs are used. No key is configured by default.

Register exact model ID, label, and current input/output rates in USD per million tokens. Discovery lists candidates from the provider, but no prices are inferred. Enabled registered models appear in scenario creation. Disabling a model/provider stops new requests even for existing scenarios; transcripts remain intact. Settings shows linked scenario counts. Demo is an embedded tiny word-transition generator, not a neural LLM or a clinical assistant. It makes no provider request and incurs no provider cost, but normal platform usage controls apply.

Per-provider and global monthly budgets use atomic D1 reservations with conservative byte-based input allowances and full output cap. Actual reported input and output tokens replace the reservation after a successful response; failed/missing usage retains it. Costs are estimates using admin-entered prices, not billing invoice data. Incorrect pricing, provider tokenization/overhead, caching, or upstream billing may differ. No provider-side budget has been set. API spend limits independent of scenario No limit. Demo represented internally by reserved model ID brite-demo-local because the original DB provider check accepts only openai/anthropic; send path handles it locally before resolving credentials. Existing scenarios can resume paid chat once their exact model is registered.
