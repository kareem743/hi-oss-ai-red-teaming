# Scenario conversation limits

The scenario editor has two independent optional dropdowns. Blank values use the existing hard defaults (25 turns, 80,000 input-text characters). A turn is a reserved request to the model; failed attempts count too. The context cap counts the system prompt, completed user/assistant history, and next user message in Python Unicode characters before sending. It is not a tokenizer-specific token or dollar cap; the provider's response may push the stored history past the cap, after which another turn is blocked. The existing 512 default output-token setting, 50 model requests per volunteer per UTC day, and 8,000-character prompt limit remain. Restarting a conversation resets its two per-conversation limits but does not reset the daily request budget. The volunteer can still flag and finish a limited chat. Migration 0004 adds checked scenario columns with defaults for existing records. All changes require the CI quality gate before packaging/deployment.

Migration 0005 adds an explicit No limit checkbox (checked by default in the new editor). It disables both per-scenario limits and hides chat counters. Existing scenarios keep their prior limits. Daily 50-request and per-message/output safeguards remain. API callers omitting no_limit retain the previous defaults.
