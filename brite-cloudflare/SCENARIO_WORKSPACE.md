# Scenario-first workspace\n\nPublic scenarios are visible to all approved volunteer accounts. Private scenarios grant membership to the explicitly assigned emails and approve previously unknown emails as volunteers. Cloudflare Access verifies email identity; the application enforces its own active-account and scenario-level authorization. A public scenario is not anonymously accessible. Admins create a scenario with instructions, audience and model, and view complete conversations or flagged-only conversations. Volunteers have one scenario list and a simple chat screen. Existing campaign, task, export and review APIs remain available. Model API credentials are still required.\n
## Live release

The scenario-first interface and FastAPI routes are deployed to https://brite-redteam-api.kareem-rag-tools.workers.dev/. Migration 0002 is applied and the existing database has no foreign-key violations. The website reuses the Medical Tool's exact shield, Urbanist font, navy/coral palette, and top-navigation design. The new frontend uses browser ES modules and CSS rather than a React runtime; Vite production build remains available. The live upload packages these text assets directly with the Python Worker because the asset-session upload authorization limitation remains.

The dedicated Access application allows one-time email PIN identity verification. All research API routes additionally require a verified JWT and an active D1 user; scenario-level permission and conversation ownership are checked server-side. An unapproved email can authenticate its identity, but cannot access research records. This makes assignment by email possible without editing the Cloudflare policy for each person. No anonymous research access is enabled.

Four backend tests, the frontend production build, and Python package build passed in GitHub Actions run 45949864136. Live authenticated scenario creation, volunteer sign-in, provider calls and flagging still require browser acceptance testing. No provider secrets were configured, no volunteer accounts were added during this release, and no existing research records were deleted.
