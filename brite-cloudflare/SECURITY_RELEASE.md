# Security release notes

Cloudflare Access OTP verifies identity; application approval is mandatory before research access. First verified unapproved login creates one pending request, keyed to the verified JWT email. Rejection persists. Removal revokes membership, preserves transcripts, and allows a new request. Blacklist persists until administrator unblocks. Requests appear in Volunteers; no automatic email notification is configured.

All LLM calls use server secrets and fixed HTTPS provider endpoints without tool definitions or redirect following. User/model content is rendered as escaped text. System prompt is optional, stored on model configuration, and snapshotted for the conversation; never put secrets in it.

Global atomic D1 quota reservation enforces 5 model requests/user/minute, 20/IP/minute (fixed windows), 50/user/day, one pending request/user, 1,000 requests/month, 2,000,000 cumulative input UTF-8 bytes/month, 512,000 reserved output tokens/month. These are conservative usage limits, NOT a guaranteed dollar cap or exact token count. A model request reserves the full output allowance even on failure; monthly quotas use UTC. Platform caps apply even with No limit. Actual provider billing can differ; use separate provider projects, restrict keys, configure available provider credit/spend controls and billing alerts. No provider key exists in the Worker at review time. No paid upgrade or billing settings changed. Admin pause stops new reservations, not already in-flight provider calls. IP is hashed, and minute windows are cleaned by existing scheduled job.

Request body is bounded by actual bytes before parsing. Browser cross-origin writes blocked. All research API routes require approved account, including health; the access-request endpoint requires a verified identity but not approval. No custom DNS zone exists for this workers.dev deployment, so zone WAF/Bot Fight Mode cannot be configured here. Do not promise bot-proofing; email verification, D1 quotas and app checks are the main controls. Dependency scanning added to CI. Live provider and real OTP acceptance testing still required; branch protection must be configured in GitHub UI. No automatic administrator emails configured.
