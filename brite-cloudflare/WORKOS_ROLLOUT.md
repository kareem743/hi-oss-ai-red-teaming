# WorkOS rollout — Red Teaming

The application supports three explicit modes. Default `access`: current Cloudflare Access JWT and OTP. `workos-preview`: keep Cloudflare Access in front of every route, configure WorkOS and use the administrator's Test WorkOS link; the callback requires the same verified edge email. `workos`: app authorizes only a valid WorkOS session and existing D1 account permissions; invalid/incomplete configuration fails closed. Cloudflare Access remains active until manually switched after preview.

Add the exact redirect URI in the WorkOS dashboard: https://brite-redteam-api.kareem-rag-tools.workers.dev/auth/workos/callback. Configure the destination application for verified-email passwordless sign-in and allow new verified identities to request local access. Configure WORKOS_CLIENT_ID and WORKOS_REDIRECT_URI as Worker variables and WORKOS_API_KEY as an encrypted Worker secret. Never reuse or copy another app's API key from runtime. APP_ORIGIN is already set. Set BRITE_AUTH_MODE to workos-preview, test same-email admin callback, check server session and logout. Keep current access policy until testing succeeds. Then explicitly activate WorkOS and adjust only the Red Teaming Access app to let unauthenticated visitors reach the app-owned login; never change Medical Tool or other Access policies. Retain rollback: restore Access app policy and BRITE_AUTH_MODE=access. All application research endpoints remain role checked.

Production authentication is not verified until a real WorkOS flow succeeds. Mock CI covers identity, PKCE, replay, approval, blacklist, logout, and preview. Local sessions expire after 24h; WorkOS global logout uses the session ID returned by exchange if available. No password flow or direct access to research data is added. For a removed/rejected/blacklisted account, authorization is checked on every request.
